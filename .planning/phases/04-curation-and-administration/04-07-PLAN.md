  <action>
Fix three compounding issues identified in UAT Test 9 root cause analysis:

**Fix 1 — middleware.ts: use path-relative redirect (no hostname leak)**

In `src/middleware.ts`, the login redirect on line 37 currently reads:
```typescript
const loginUrl = new URL('/login', request.url);
```
This embeds `request.url`'s origin into the redirect Location header. Behind the Daytona preview proxy, `request.url` carries the external proxy hostname (e.g. `https://3000-pivota-sandbox-....preview.pivota-ng.pivota.dev`), causing the browser to land on the proxy URL instead of the app's internal /login.

Replace with `request.nextUrl.clone()` which always uses the app's own internal URL:
```typescript
const loginUrl = request.nextUrl.clone();
loginUrl.pathname = '/login';
loginUrl.searchParams.set('returnTo', pathname);
return NextResponse.redirect(loginUrl);
```

This change makes the redirect URL always path-relative to the app's own base URL, not the incoming request's possibly-proxied origin.

**Fix 2 — session.ts: SameSite=None; Secure for cross-origin iframe/proxy compatibility**

In `src/lib/auth/session.ts`, `setSessionCookie()` currently sets `sameSite: 'lax'`. When the app is accessed via the Daytona preview proxy (cross-site context), the browser silently drops SameSite=lax cookies, making the middleware see no session for a logged-in curator.

Update BOTH `setSessionCookie()` and `clearSessionCookie()` to use `sameSite: 'none'` with `secure: true` (browsers require Secure when SameSite=None):
```typescript
export function setSessionCookie(response: NextResponse, token: string): void {
  response.cookies.set(SESSION_COOKIE, token, {
    httpOnly: true,
    secure: true,          // Required when sameSite='none'; always on for preview proxy
    sameSite: 'none',      // Allow cross-site/cross-origin preview proxy delivery
    maxAge: SESSION_TTL_SECONDS,
    path: '/',
  });
}

export function clearSessionCookie(response: NextResponse): void {
  response.cookies.set(SESSION_COOKIE, '', {
    httpOnly: true,
    secure: true,
    sameSite: 'none',
    maxAge: 0,
    path: '/',
  });
}
```

Note: The production AUTH-07 guard in auth stub already gates `NODE_ENV=production`. Setting `secure: true` unconditionally is correct — the app runs HTTPS in both the Daytona preview and any real deployment. The old `secure: process.env.NODE_ENV === 'production'` was the root cause of the iframe issue.

**Fix 3 — curator/settings/page.tsx: redirect curator 403 to /unauthorized (not /curator)**

In `src/app/curator/settings/page.tsx`, on API 403 the client currently does `router.push('/curator')`. This is inconsistent with the RBAC contract — a curator denied settings access should land on /unauthorized. Change line 69:
```typescript
// Old:
router.push('/curator');
// New:
router.push('/unauthorized');
```

Create `e2e/curator-settings-rbac.spec.ts` with Playwright tests asserting the three fixed behaviors:

1. **Middleware redirect is internal** — an unauthenticated request to `/curator/settings` redirects to a `/login` URL that does NOT contain the preview proxy hostname pattern.
2. **Curator visiting /curator/settings → /unauthorized** — a curator-role user who navigates to `/curator/settings` ends up at `/unauthorized` (not `/login`, not the external proxy URL).
3. **Admin visiting /curator/settings → settings page loads** — admin role can access settings (regression: don't break happy path).

```typescript
import { test, expect } from '@playwright/test';

test.describe('Curator settings RBAC redirect (gap closure — UAT test 9)', () => {

  test('unauthenticated /curator/settings redirect stays on internal hostname (no proxy leak)', async ({ page }) => {
    // No login — cold browser (no session cookie)
    const res = await page.request.get('/curator/settings', { maxRedirects: 0 });
    // Should 307 to /login
    expect([307, 308]).toContain(res.status());
    const location = res.headers()['location'] ?? '';
    expect(location).toContain('/login');
    // CRITICAL: location must NOT contain external preview proxy hostname pattern
    expect(location).not.toMatch(/\d{4}-pivota-sandbox/);
    expect(location).not.toMatch(/preview\.pivota-ng/);
  });

  test('curator visiting /curator/settings → redirected to /unauthorized', async ({ page }) => {
    // Authenticate as curator
    await page.request.post('/api/auth/login', { data: { role: 'curator' } });
    // Navigate to settings (follows redirects)
    await page.goto('/curator/settings');
    // Should end up on /unauthorized — not /login, not settings
    await expect(page).toHaveURL(/\/unauthorized/);
    await expect(page.getByRole('heading', { name: /access restricted/i })).toBeVisible();
  });

  test('admin visiting /curator/settings → settings page loads (regression)', async ({ page }) => {
    // Authenticate as admin
    await page.request.post('/api/auth/login', { data: { role: 'admin' } });
    await page.goto('/curator/settings');
    // Should NOT be redirected away
    await expect(page).toHaveURL(/\/curator\/settings/);
    await expect(page.getByRole('heading', { name: /hub settings/i })).toBeVisible();
  });

  test('curator settings API returns 403 for curator role', async ({ page }) => {
    await page.request.post('/api/auth/login', { data: { role: 'curator' } });
    const res = await page.request.get('/api/v1/curator/settings');
    expect(res.status()).toBe(403);
  });
});
```
