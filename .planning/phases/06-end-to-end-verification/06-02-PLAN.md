<objective>
Execute the full requirement test suite, present every failure to the user with context (requirement text, test name, failure error), ask for root cause classification, and produce a triage report that drives plan 06-03 fixes.

This plan is INTERACTIVE — it runs tests, stops at each failure, and asks the user questions before proceeding. The user is the decision-maker on whether each failure is a bug, gap, or accepted design decision.

Workflow per failure:
1. Show the failing REQ-ID and requirement text
2. Show the test failure error/evidence
3. Ask: "What is the root cause? Is this a bug, a gap (feature not yet built), or a design decision (expected behavior)?"
4. Record the user's answer in TRIAGE-REPORT.md
5. Move to the next failure
</objective>

**Step 3: Triage loop — for each failure, ask the user.**

For EACH failing requirement, present this information and ask:

```
╔══════════════════════════════════════════════════════════════╗
║  CHECKPOINT: Requirement Failure                             ║
╚══════════════════════════════════════════════════════════════╝

Requirement: [REQ-ID] {full requirement text from REQUIREMENTS.md}

Test name: {test title}
Failure: {error message}

What is the root cause?
```

Use the question tool with options:
- **Bug** — The feature is built but there is a code defect causing incorrect behavior
- **Gap** — This feature or behavior has not been implemented yet
- **Design Decision** — The implemented behavior intentionally differs from the requirement; requirement should be updated
- **Needs Investigation** — I need to check the live app before classifying

For each "Bug" or "Gap" classification, also ask:
```
What fix is needed? (brief description — will be used in plan 06-03)
```

Record every answer in TRIAGE-REPORT.md with this format:

```markdown
# Triage Report — TechSur Innovation Hub
**Run date:** {date}
**Total failures triaged:** {N}

## Failure Triage

| REQ-ID | Description | Classification | Root Cause | Proposed Fix | Priority |
|--------|-------------|----------------|-----------|--------------|---------|
| [REQ-ID] | [requirement text] | Bug / Gap / Design Decision / Accepted | [user description] | [fix plan] | High / Medium / Low |
```
